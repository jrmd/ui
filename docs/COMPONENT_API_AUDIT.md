# Component API audit

Scope: all 91 catalogue components. Reviewed canonical public props, rendered structure, built-in styles, content extension points, and installation examples. This is an API and composition audit, not a claim that every possible user composition has been accessibility-certified.

Standard: common use requires no Tailwind classes. Structural components expose named styled parts; atomic controls retain useful direct APIs; data-driven controls and charts accept content/data without making callers rebuild their internals. className is an override. Existing shortcut APIs remain supported.

## Installation and verification

The catalogue lists named exports alongside each API. Compound parts are installed from the same canonical source file as their parent. Generated examples resolve all compound imports to their owning registry item; this is checked by installing and compiling examples in Vite and Next.js. See [composition examples](COMPOSITION.md) and [verification](VERIFICATION.md).

Layout remains a caller decision for the surrounding page. Cards, fields, overlays and menus supply their internal spacing. Motion text inherits the surrounding font size deliberately. For low-level fields, preserve matching htmlFor/id and aria-describedby when assembling labels manually; FormField handles these automatically.
